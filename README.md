## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

[`src/main/kotlin/lab2/ProductSelection.kt`](src/main/kotlin/lab2/ProductSelection.kt)

**Как работает функция и почему выбран такой способ обработки данных?**

Функция сначала строит по каталогу словарь `productsById`, где ключом является `id` товара, а значением — полный объект `Product`. Затем идентификаторы исключений преобразуются в `HashSet`. После этого рекомендации просматриваются в исходном порядке: для каждого `id` функция находит товар в словаре и добавляет его в результат, только если товар существует, доступен, не исключён и ещё не был добавлен.

Такой способ выбран, чтобы не искать товар перебором по каталогу для каждой рекомендации. Поиск по `HashMap` и проверка `HashSet` выполняются в среднем за постоянное время, поэтому решение подходит для большого каталога и большого числа рекомендаций. Входные списки не изменяются: результат формируется в новом списке.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Порядок результата определяется порядком обхода `recommendedIds`: функция добавляет товар в результат при первом появлении его идентификатора в рекомендациях. Порядок товаров в каталоге на результат не влияет, так как каталог используется только для поиска товара по `id`.

Уникальность обеспечивает множество `addedIds`. Перед добавлением товара функция пытается добавить его `id` в это множество: если идентификатор уже встречался, повторное добавление не выполняется. Исключённые товары пропускаются по множеству `excluded`, недоступные — по значению `available = false`, а идентификаторы, отсутствующие в каталоге, не дают результата при поиске в `productsById` и также пропускаются.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

\(O(p + r + e)\).

Построение словаря `productsById` по каталогу выполняется за \(O(p)\), а преобразование `excludedIds` в множество — за \(O(e)\). Затем функция один раз проходит по всем \(r\) рекомендациям; для каждой рекомендации поиск товара в `productsById`, проверка исключения и проверка `addedIds` выполняются в среднем за \(O(1)\). 

**Дополнительная память:**

\(O(p + e + k)\), где \(k\) — число товаров в итоговой подборке.

Словарь `productsById` хранит ссылку на каждый товар каталога и занимает \(O(p)\). Множество `excluded` хранит исключённые идентификаторы и занимает \(O(e)\). Множество `addedIds` содержит только идентификаторы уже добавленных товаров, поэтому занимает \(O(k)\).

Память для результата указывается отдельно: список `result` содержит \(k\) ссылок на объекты `Product` и занимает \(O(k)\). Сами объекты товаров при этом не копируются; функция использует уже существующие объекты из каталога.
